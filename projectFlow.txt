Project Deployment Workflow

1. Start Deployment
- The web user selects the entire project or specific KM (Kilometer) sections for deployment.
- A department can assign a DEPLOYMENT CONTRACTOR for those selected KM sections.
- If it's a new project, deployment can be skipped and the project can directly move to the Construction stage.

2. Define Work Sequence
- The web user selects an existing work execution template or creates a new one.
- The template defines the order in which construction activities should be performed.

3. Assign Ground Work
- The DEPLOYMENT CONTRACTOR assigns work to field employees.
- Employees are assigned construction blocks such as:
  • Road sections
  • Railway sections
  • Tunnels
  • Earthwork
  • Bridges
  • Metro structures

4. Update Ground Status
- Field staff use the tablet application.
- They update the status of each road block or object according to the template.
- Example:
  • Not Started
  • In Progress
  • Completed

5. Verify the Updates
- Deployment contractor or project owner reviews the updates.
- After verification, the system officially accepts the deployment.

6. Confirm KM-wise Deployment
- Each KM must be confirmed separately.
- Possible status changes: No work done → Change KM status to "Construction".
- Work completed with all assets installed → Change KM status to "Maintenance".

7. Assign Drone Contractor
- After deployment is confirmed, one or more KM sections can be assigned to a drone contractor.
- Before assigning:
  • Drone flight path must be uploaded.
  • Drone flying conditions must be configured.

8. Configure Drone Work
- A drone contractor can manage multiple KM groups (packets).
- Each group can have different settings, such as:
  • Flight schedule
  • Inspection frequency
  • pload time

9. Start Construction
- Once a KM status becomes Construction, the project owner can assign:
- assets contractors

10. Measurement Work
- The project owner assigns a measurement contractor.
- The measurement team measures completed work using drone-generated point cloud data.
- Their web user reviews and approves the measurements.

11. View Progress
- After approval, the project owner can.
• View measured quantities.
• Compare drone data from different dates.
• Monitor KM-wise work progress.
• Check work completion status.

12. Track Project Timeline
- If KM-wise targets are entered into the system, it can automatically show whether the project is:
  • On schedule
  • Delayed
  • Ahead of schedule

1) What is point cloud data?
- Point cloud data is collection of millions of 3D points that represents shape and surface of real world objects.
- It is created using technology like drones, LiDAR(Light Detection and Ranging)


3) What are the file extensions used for point cloud data?
- .LAS, .LAZ, .PLY, .PCD, .E57


4) How can we identify vegetation in point cloud data?
- Vegetation can be identify by 
  1. Height - trees and plants
  2. shape and density - Vegetation has irregular, scattered point patterns compared to buildings or roads.
  3. Classification Algorithms: LiDAR software automatically classifies points as ground, vegetation, buildings, etc.
  4. Color (RGB): If color information is available

 
5) How many axes are present in point cloud data?
- 3 axes 
- x, y, z


6) How can we calculate the volume? What different methods can be used?
- volume is calculated by comparing the 3D surface with a reference surface
• Cut and Fill Method – Calculates the amount of material "cut" and added (fill) by comparing two surfaces.
• Grid Method – Divides the area into small grid cells and calculates the volume of each cell, then sums them.
• TIN (Triangulated Irregular Network) Method – Creates a mesh of triangles from the point cloud and calculates the volume between the mesh and the reference surface.
• Mesh
Example 1: Stockpile (Sand Heap)

_____/______\_____ ← Base Surface (ground)

Example 2: Excavation (Pit)

      \      /
       \____/  ← Mesh (bottom of the pit)


8) How can we calculate the height and width of a 3D object?
- Height is the difference between the highest Z-value and the lowest Z-value of the object.
- Width is the distance between the leftmost and rightmost points (X-axis) or frontmost and backmost points (Y-axis), depending on the object's orientation.


9) Which libraries are used to visualize point cloud data, and why?
- Three.js – A JavaScript library used to render interactive 3D graphics and point clouds in web applications using WebGL.
(webGL(Web Graphics Library) - its a JS api allows web browser to render high performance 2D and 3D graphics)
- Open3D – A Python/C++ library used for point cloud visualization, processing, and analysis in desktop and research applications.


10) What is 3D meshing?
- 3D meshing is process of converting point cloud into continuous 3D surface by connecting near by points in triangle or pollygon formats


11) What are the units of the 3D point cloud data coordinates?
- The co-ordinates in 3D point cloud data are x,y,z measured in meter(m)
- but in sometimes also in millimeters(mm), centimeters(cm)

Que) Haw point cloud data is converted into 3D graphical model?
-Point cloud data is converted into a 3D graphical model through several processing steps:
 step 1: Capture Data – Drones or LiDAR scanners collect millions of 3D points (X, Y, Z coordinates).
 step 2: Process the Point Cloud – Noise and unwanted points are removed, and the data is aligned and cleaned.
 step 3: Create a 3D Mesh – Nearby points are connected using triangles or polygons to form a continuous surface.
 step 4: Apply Colors or Textures – Images or RGB data are added to make the model look realistic.
 step 5: Visualize – The final 3D model is displayed using software or libraries like Three.js, or Open3D, allowing users to rotate, zoom, and measure the model.

Here's the difference between .LAS, .LAZ, and .PLY in simple terms:

.LAS
- LASer file
- Stores LiDAR point cloud data
- Compression: NO
- File size: large
- contains xyz coordinates, GPS, colors

.LAZ
- Compressed LAS
- Stores compressed LiDAR point cloud data
- Compression: YES
- File size: smaller (50-90%)
- Same as LAS

.PLY
- Polygon file format
- Stores 3D model or point cloud data
- Compression: NO
- File size: Medium
- Contains: MESH, color

2) A typical buried pipeline consists of the following layers:

• Top Soil: The upper fertile soil layer, Removed before excavation and stored separately.Placed back on top after construction.
• Compacted Backfill: Soil filled above warning tape and restores the ground strength
• Warning Tape: Warns anyone digging that a buried utility exists below. 
• Initial Backfill: Fine soil and sand placed above the pipe. protects the pipe from rock and heavy loads
• Side Fill: Material packed around the pipe to hold pipe in it's position
• Pipe: Then main pipe
• Sand Bedding: A layer of thin sand placed beneath the soil provides a smooth surface level
• Foundation (if required) : Used only when the natural soil is weak, soft, or unstable.
• Natural Soil: The original undisturbed soil before excavation.


3) Pipe joints

- Butt weld (steel)

4) Why sand bedding is imp:

- With bedding: Uniform support, Better load dustribution, Long life

  • Types of merge
    1. junction merge / intersection merge
       - Road is made up of meny coordinates P1 ---- P2 ---- P3 ---- P4 ---- P5 ---- P6
       - so which point of main road A has closest to road B point
       - get their coordinates(xyz) find tolerance
       - if the tolerance(error limit/allowed deviation) is less than expected we can merge.
    
    2. extension merge
       - Here we expect start and end coordinates
       - Start Point (X,Y,Z)  End Point (X,Y,Z)
       - if road A has end points End(500,200,10) and road B has start points Start(501,200,10) if the difference bwt road A end and road B start is < tolerance then            we can merge else not
